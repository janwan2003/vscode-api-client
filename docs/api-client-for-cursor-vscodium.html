An API client for Cursor, Windsurf and VSCodium

Cursor, Windsurf and VSCodium are built on VS Code, but they install extensions from Open VSX rather than from Microsoft’s Marketplace. Some API clients are missing there, out of date, or ask you to sign in before the first request. Plainwire is a free, open-source GUI API client that runs in all of them, needs no account, and keeps your requests as plain .http files next to your code, where your editor’s AI assistant can read and edit them too.

Plainwire is an independent open-source project, not affiliated with Cursor, Windsurf, VSCodium, Thunder Client, Postman or REST Client.

Install it in Cursor, Windsurf or VSCodium

Plainwire is not on Open VSX yet (the listing is coming), so for now you install the same file VS Code users get:

  1. Download the plainwire-<version>.vsix file from the latest GitHub release.
  2. Install it. Open the Command Palette (Ctrl+Shift+P, or Cmd+Shift+P on macOS) and run Extensions: Install from VSIX…, or drag the file onto the Extensions view. From a terminal: 
    cursor --install-extension plainwire-0.5.0.vsix
codium --install-extension plainwire-0.5.0.vsix
windsurf --install-extension plainwire-0.5.0.vsix
  3. Open a folder with a .http file, or run Plainwire: New Request. A Send Request link appears above each request; Open in Plainwire opens the form editor.

Updates: a manually installed .vsix does not update itself. Watch the releases page (GitHub “Watch → Custom → Releases”) until the Open VSX listing is live.

Why plain files suit AI editors

A collection stored in an extension’s private database is invisible to your editor’s assistant. A .http file is just text in the repository, so you can ask the assistant to “add a request for the new /orders endpoint with a check that it returns 201” and get a reviewable diff:

### Create order
# @name createOrder
# @assert status == 201
# @assert $.id exists
POST {{baseUrl}}/orders
Content-Type: application/json
Authorization: Bearer {{token}}

{ "sku": "TSHIRT-M", "quantity": 2 }

The same file opens as a form in Plainwire, runs in the collection runner, and runs in CI with the free command-line runner. The format is the one REST Client and JetBrains IDEs use; see the .http syntax cheat sheet.

What you get

  • A form editor (method, URL, params, headers, body, auth, tests) and a response viewer with a JSON tree, headers and timing.
  • Environments from http-client.env.json, .env values and the REST Client settings you may already have.
  • Request chaining, # @assert tests and a Run all report for a file or a folder.
  • One-click import from Thunder Client, Postman and cURL.
  • No login, no telemetry, no request or run limits. Requests are sent by Node in the extension host, so CORS does not apply and localhost works.

Questions

Do I need a Microsoft or Open VSX account?

No. Installing a .vsix needs no account at all, and Plainwire itself never asks you to sign in.

Will my settings and history follow me between editors?

Your requests are files in the repository, so they are the same in every editor. Request history is stored per workspace by each editor, so it does not move.

Can I use it next to REST Client or Thunder Client?

Yes. Plainwire only reads .http/.rest files and its own local history; it does not touch other extensions’ data.
