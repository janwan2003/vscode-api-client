A REST Client alternative that keeps your .http files

REST Client made .http files the way to keep API requests next to your code in VS Code. Its last release, 0.25.1, came out in August 2022, and its issue tracker has 528 open issues. Plainwire opens the same files, unchanged, and adds what REST Client users ask for most: a form editor and response viewer, importing one .http file into another, running every request in order, assertions, and a command-line runner for CI. It is free and open source, needs no account and sends nothing except your requests.

Plainwire is an independent open-source project. It is not affiliated with or endorsed by REST Client or its author.

What stays the same

  • Your .http and .rest files: ### separators, @variable = value, {{variable}}, # @name and request chaining with {{login.response.body.$.token}}, < ./file.json bodies, multipart, GraphQL with X-REQUEST-TYPE: GraphQL, and system variables such as {{$guid}}, {{$timestamp}}, {{$dotenv NAME}}.
  • Your environments in the rest-client.environmentVariables setting, including $shared.
  • Plain text in git: Plainwire writes back only the request you edit, byte for byte elsewhere, so diffs stay small. You can keep both extensions installed.

What you get on top

  • A GUI: click Open in Plainwire above any request for a form with params, headers, body, auth and tests, and a response viewer with a JSON tree, headers and timing. Edits are saved into the .http file.
  • Tests as # @assert lines and Run all with a pass/fail report you can copy as Markdown.
  • A CLI and a GitHub Action that run the same files in CI.
  • Copy as Code in 11 languages, with variables resolved (try it online).
  • Import from Postman, Thunder Client, OpenAPI / Swagger and cURL into .http files.
  • Self-signed certificates per request, any port, HTTP proxies (guide).

Switch in a minute

  1. Download plainwire-0.15.0.vsix from the latest release and run Extensions: Install from VSIX… (works in VS Code, Cursor, Windsurf and VSCodium).
  2. Open a folder with your .http files. Each request gets Send | Open in Plainwire | Copy as Code… above it, and the Plainwire sidebar lists every request in the workspace.
  3. Pick an environment in the status bar; your rest-client.environmentVariables are already there.

What Plainwire does not do (yet)

Being honest about the gaps: no gRPC, no SOCKS proxies or client certificates. Scripts run only in the JetBrains format; httpYac’s {{ }} script blocks are not run. REST Client’s Markdown-embedded requests and rest-client.* settings other than environments are not read. If you rely on one of these, REST Client may still be the better fit.

FAQ

Is REST Client abandoned?

We cannot speak for its author. The facts: the last Marketplace release is 0.25.1 from 19 August 2022 and the repository has 528 open issues (both read on 20 November 2026). The extension still works for many people, and its 4.9-star rating is well earned.

Can I use both extensions at once?

Yes. Both read the same files. Each adds its own CodeLens above requests; you can turn REST Client’s off with its rest-client.enableSendRequestCodeLens setting if the row gets crowded.

Does Plainwire need an account or send telemetry?

No. It makes no network requests except the ones you send, and the source is on GitHub (MIT).
