Convert Thunder Client collections to .http files

Thunder Client stores collections as JSON in its own format. A .http file holds the same information as readable text that lives in your repository and runs in Plainwire, REST Client and JetBrains IDEs. This guide shows the one-click route with Plainwire and, for anyone who prefers to do it by hand, exactly how each Thunder Client field maps to the format.

Want the files right now? Choose your Thunder Client export (or the thunder-tests JSON files) in the online Thunder Client to .http converter. It runs in your browser; nothing is uploaded.

Step 1: get your data out of Thunder Client

You need either an exported collection file or a thunder-tests folder.

  • Exported collection. In the Thunder Client sidebar, open Collections, click the … menu next to the collection and choose Export. Repeat for each collection. Export environments from the Env tab the same way.
  • thunder-tests folder. Projects that used Thunder Client’s save-to-workspace or Git Sync option have a thunder-tests folder in the repository that already contains collections and environments as JSON. Plainwire can import that folder as a whole.

An exported collection looks roughly like this (shortened; real exports contain more fields, and the layout varies between Thunder Client versions):

{
  "clientName": "Thunder Client",
  "collectionName": "Shop API",
  "folders": [
    { "_id": "f1", "name": "Orders", "containerId": "" }
  ],
  "requests": [
    {
      "_id": "r1",
      "containerId": "f1",
      "name": "Create order",
      "method": "POST",
      "url": "{{baseUrl}}/orders?dryRun=false",
      "params": [ { "name": "dryRun", "value": "false" } ],
      "headers": [ { "name": "Accept", "value": "application/json" } ],
      "auth": { "type": "bearer", "bearer": "{{token}}" },
      "body": { "type": "json", "raw": "{\"sku\":\"TSHIRT-M\",\"quantity\":2}" },
      "tests": [ { "type": "res-code", "custom": "", "action": "equal", "value": "201" } ]
    }
  ]
}

Step 2: import with Plainwire

  1. Install Plainwire from the latest .vsix release (install steps).
  2. Open the folder where the requests should live, then run Plainwire: Import from Thunder Client… from the Command Palette (or the button in the Plainwire sidebar). If the workspace has a thunder-tests folder you can import it directly; otherwise choose Thunder Client.
  3. Select the exported .json file or the thunder-tests folder. Plainwire writes .http files into the workspace; they appear in the sidebar under Collections straight away.
  4. Open a file, check a request or two with Send Request, and commit.

The request above comes out along these lines (exact header order and formatting may differ):

### Create order
# @name createOrder
POST {{baseUrl}}/orders?dryRun=false
Accept: application/json
Authorization: Bearer {{token}}
Content-Type: application/json

{"sku":"TSHIRT-M","quantity":2}

System variables

Thunder Client writes its dynamic values with a # prefix; the .http format uses $. After importing, search your files for {{# and replace any that remain:

Thunder Client.http
{{#guid}}{{$guid}}
{{#timestamp}}{{$timestamp}}
{{#dateISO}}{{$datetime iso8601}}
Random number{{$randomInt 0 1000}}

Environments

A Thunder Client environment is a named list of variables. In the .http world, all environments live in one http-client.env.json next to your requests, keyed by name:

{
  "local":   { "baseUrl": "http://localhost:3000" },
  "staging": { "baseUrl": "https://staging.example.com" }
}

Put secrets in http-client.private.env.json with the same environment names, and keep that file out of git:

{
  "local":   { "token": "dev-token" },
  "staging": { "token": "replace-me" }
}
# .gitignore
http-client.private.env.json

Converting by hand

For a handful of requests you can also copy them over manually. A layout that works well:

api/
  orders.http            one file per Thunder Client folder
  auth.http
  http-client.env.json   shared, committed
  http-client.private.env.json   secrets, gitignored

Write each request with a ### title, add # @name to any request whose response you reuse (for example a login that returns a token), and replace Thunder Client’s “set env from response” steps with request chaining:

### Log in
# @name login
POST {{baseUrl}}/auth/login
Content-Type: application/json

{ "email": "{{user}}", "password": "{{password}}" }

### Create order
POST {{baseUrl}}/orders
Authorization: Bearer {{login.response.body.$.token}}
Content-Type: application/json

{ "sku": "TSHIRT-M", "quantity": 2 }

After the import: checklist

  • Search for {{# and replace leftover Thunder Client system variables.
  • Move tokens and passwords out of http-client.env.json into the private file.
  • Note which requests had tests or scripts; those checks need to be done by hand for now.
  • Send one request per environment to confirm the values resolve.
