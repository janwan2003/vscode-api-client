A free Thunder Client alternative without login

Thunder Client made a GUI API client inside VS Code popular. Its recent versions ask you to sign in before you can send requests, and the free plan now has limits. If you only want to fill in a URL, press Send and keep your requests next to your code, Plainwire does that for free, with no account and no limits, and stores everything as plain .http files in your repository.

Plainwire is an independent open-source project. It is not affiliated with or endorsed by Thunder Client, Postman or REST Client.

What changed in Thunder Client

According to the Thunder Client pricing page (as read on 20 November 2026), the free plan allows 50 requests per collection and 50 collection runs per month, while Git Sync and custom scripting are on paid plans. Recent versions also require signing in to an account to send requests, which is the most common complaint in the extension’s recent marketplace reviews. Thunder Client remains a capable product with features Plainwire does not have yet; if those limits do not affect you, there may be no reason to switch.

How to switch in five minutes

  1. Export your collections from Thunder Client. In the Thunder Client sidebar, open the Collections tab, open the menu (…) next to a collection and choose Export. You get a JSON file such as thunder-collection_Shop API.json. Do the same for each environment in the Env tab. If your project already has a thunder-tests folder (written by Thunder Client’s save-to-workspace or Git Sync feature), you can skip this step and import the folder directly.
  2. Install Plainwire. Download the .vsix from the latest release and run Extensions: Install from VSIX… (see install steps).
  3. Import. Run Plainwire: Import from Thunder Client… (Command Palette, or the button in the Plainwire sidebar), and pick the exported JSON file(s) or the thunder-tests folder. Plainwire writes the requests as .http files into your workspace.
  4. Set up environments. Imported environment values go into http-client.env.json. Move secrets (tokens, passwords, API keys) into http-client.private.env.json and add that file to .gitignore.
  5. Commit. Review the new .http files, send a couple of requests from the Send Request links, and commit them. Your teammates get the collection with their next git pull, no account needed.

The full field-by-field mapping is on Thunder Client collections to .http files.

What a migrated request looks like

A Thunder Client request with a bearer token, a query parameter and a JSON body becomes a block like this:

### Create order
POST {{baseUrl}}/orders?dryRun=false
Authorization: Bearer {{token}}
Content-Type: application/json

{
  "sku": "TSHIRT-M",
  "quantity": 2
}

It is readable in code review, works in REST Client and JetBrains IDEs, and opens as a form in Plainwire.

What does not carry over

  • Tests and scripts. Plainwire has no JavaScript scripting, so pre/post-request scripts are not imported. Since 0.2.0, the common Thunder Client tests (status, response time, body and header checks, JSON values, counts and types) are converted to # @assert lines you can run with Run all; see API tests in .http files. Scripts are still not imported.
  • Request history. Your Thunder Client activity history stays in Thunder Client; Plainwire starts its own local history.
  • OAuth 2 (Client Credentials, Authorization Code with PKCE, Password, Device flow) works since 0.10: see OAuth 2.0 tokens in .http files. WebSocket and gRPC are not available in Plainwire yet. GraphQL requests are imported with their query and variables.

Why plain files

A collection that lives in a vendor’s storage can be limited, moved behind a login or lost in an update. A .http file in your repository cannot: you can read it, diff it, review it and run it with several different tools. That is the main design choice behind Plainwire, and the reason it never needs an account.

Questions

Will Plainwire add limits or a login later?

The core client is MIT-licensed open source, so it can always be used, forked and built without an account. Sending requests, collections, environments and imports are part of that open-source core.

Can I use Plainwire and Thunder Client side by side?

Yes. They do not share storage. Plainwire only touches .http / .rest files and its own local history.
