Support

Plainwire is supported through GitHub issues. Search the existing issues first; if nothing matches, open a new one. Questions, bug reports and feature requests are all welcome there.

Troubleshooting

“self-signed certificate” or “unable to verify the first certificate”

Plainwire v0.1 does not yet support self-signed certificates or an option to skip certificate verification. Requests to servers with an untrusted certificate fail with a TLS error. Options until support lands:

  • Use plain http:// for local development servers where that is possible.
  • Use a certificate signed by a locally trusted CA (for example one created with a tool such as mkcert).
  • For a corporate CA, Node reads extra root certificates from the NODE_EXTRA_CA_CERTS environment variable when a process starts. Starting your editor from a shell where it points to your CA file may help; we have not tested this in every editor.

If you need this, add a thumbs-up or your use case to the relevant issue so it gets prioritised.

Requests behind a proxy

Plainwire has no proxy settings of its own yet. Requests are sent by Node in the editor’s extension host, so they follow Node’s defaults and whatever proxy support your editor provides to extensions. If requests fail behind a corporate proxy, open an issue with your editor name and version and how the proxy is configured (without credentials).

Where is my history stored?

History of sent requests (the last 100 by default, setting plainwire.historySize) is kept locally in VS Code’s per-workspace extension storage, inside your editor’s user data folder (for VS Code on Linux that is under ~/.config/Code/User/workspaceStorage/; on macOS ~/Library/Application Support/Code/User/; on Windows %APPDATA%\Code\User\; Cursor, Windsurf and VSCodium use their own folder names). It never leaves your machine through Plainwire. To clear it, use the Clear History button in the History view. Your saved requests are not in history: they are the .http files in your workspace.

A variable shows up literally as {{name}}

  • Check that an environment is selected and that it defines the variable, in http-client.env.json, http-client.private.env.json or the rest-client.environmentVariables setting.
  • File variables (@name = value) must be defined in the same file.
  • For chained values like {{login.response.body.$.token}}, send the named request (# @name login) first.

My file does not appear in the sidebar

Collections list files ending in .http or .rest inside the open workspace folder. Files outside the workspace, or excluded by your editor’s file exclusion settings, may not be listed.

An import came out wrong

Scripts and tests from Thunder Client or Postman are not imported, because Plainwire does not run scripts yet. If a request, header or body is missing or wrong, please report it with a minimal, secret-free copy of the exported file.

How to report a bug

  1. Update to the latest release and check the problem still happens.
  2. Open a new issue and include:
    • the Plainwire version and your editor and version (VS Code: Help → About), and your operating system;
    • the smallest .http snippet, cURL command or import file that shows the problem;
    • what you expected, and what happened instead (the error message, or the response status);
    • any errors from Help → Toggle Developer Tools → Console or the Output panel.
  3. Remove secrets first. Replace tokens, passwords, API keys, cookies and private hostnames with placeholders. Issues are public.

Security problems should not be reported in a public issue with exploit details; open an issue asking for a private contact channel instead, without the details.
